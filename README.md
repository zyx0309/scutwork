# OSM 铁路网络：人工智能课程大作业第一阶段

本项目处理真实 OpenStreetMap PBF 数据，构建中国 34 个省级行政区代表城市的铁路连接图，并单独计算 **广州站 → 兰州站** 的最短几何铁路路径。城市节点采用省会、首府、直辖市和特别行政区代表城市口径；保留没有铁路连接或无法匹配车站的节点。

**最新状态：用户已在 Windows 完成全国真实 PBF 处理，并上传 8 份结果表；现提供 [Word、PDF 与成果包](report/README.md)。** 云端独立核验了这些导出表，没有重新读取全国 PBF 或完整轨道 GeoJSON。真实结果图含 34 城市、351 条边、8 个连通分量；当前模型下广州→兰州候选最短几何里程为 2383.542 km。

**已确认数据问题：福州被自动误配为台湾“浮洲”站，报告已拒绝该身份映射。** 原始自动接入 30 个站不等于 30 个已验证正确站；排除已知错误后剩 29 个候选，其中 24 个空间匹配仍待复核（包含兰州）。原始输出保留，派生审计表另列，不补造车站或铁路连接。详细限制见 [报告阅读说明](report/README.md)。

**站点身份修正版已提供：[下载与 Windows 更新步骤](STATION_FIX_GUIDE.md)。** 名称冲突和距城市超过 80 km 的候选直接拒绝，中文规范别名优先；旧图缓存自动失效，提取子集可复用。双击 `run_fixed.bat` 会先备份旧输出再重跑。修正版通过小型测试，尚未完成新的全国真实运行；下面的报告结果仍属于修复前的审计记录。

最初云端仅完成代码检查及小型人工 PBF 测试；Geofabrik 下载被代理 403 拦截后，用户选择 Windows 本地真实处理。项目不包含大型 PBF，不比较 Dijkstra/A*，不生成 34×34 距离矩阵。

Windows 从解压开始的详细步骤见 [WINDOWS_GUIDE.md](WINDOWS_GUIDE.md)。安装 **Python 3.12 64 位** 后，依次双击 `install.bat`、放入两份 PBF、双击 `run.bat` 即可。运行窗口显示分阶段进度，结束时需要按键才关闭；日志保存在 `logs/`。

## 输入与安装

必需输入：

```text
data/raw/china-latest.osm.pbf
data/raw/taiwan-latest.osm.pbf
```

也支持每个区域唯一一份六位或八位日期文件名，如 `china-261013.osm.pbf`、`taiwan-20261013.osm.pbf`。`latest` 优先；多份日期版且没有 `latest` 时要求明确选择。数据日期仍来自 PBF 头，不由文件名推断。已有缓存时保持现有输入文件名。

默认只读本地文件，**不强制联网**。先验证 PBF 文件头并记录 SHA-256；流式提取完成才标记完整解析成功。没有从上游取得 MD5 的本地文件明确记录 `not_checked_offline`，不宣称通过上游校验。数据日期使用 PBF 文件头中的复制时间；缺少该字段时日期为未知，不用下载时间或文件修改时间冒充数据日期。不同日期的文件保留各自日期并记录对象版本冲突。

Linux/macOS 命令（中文字体需已安装，例如 Noto Sans CJK）：

```sh
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python tools/launcher.py --test
.venv/bin/python tools/launcher.py
```

Windows PowerShell 命令见专门指南；无需激活虚拟环境，也无需 C++ 编译器。依赖版本已经检查有 Python 3.12 / Windows x64 二进制 wheel，但没有在 Windows 系统上执行安装脚本。

只有用户主动指定 `--download` 时才联网下载缺少的文件；使用 curl 的 HTTPS、失败重试、`.part` 断点续传，核对 Geofabrik MD5 及解析器文件头。已存在但无效的文件会报错并保留，避免覆盖用户数据。若最新文件在断点续传期间发生版本轮换，校验会拒绝混合文件；须确认后删除旧 `.part` 再完整下载。

可选广东补充文件放到 `data/raw/guangdong-latest.osm.pbf`，使用 `run.bat --with-guangdong`。程序不会因缺少港澳数据而偷偷联网。结果中的覆盖和定位检查用于判断是否需要补充。

## 城市顺序与代表站

交付 CSV 始终按以下顺序排列：

北京、天津、上海、重庆、石家庄、太原、呼和浩特、沈阳、长春、哈尔滨、南京、杭州、合肥、福州、南昌、济南、郑州、武汉、长沙、广州、南宁、海口、成都、贵阳、昆明、拉萨、西安、兰州、西宁、银川、乌鲁木齐、台北、香港、澳门。

代表站选择在 `src/railway/config.py` 明确列出。多数城市选择名称对应的主要铁路站；重庆选重庆北站，成都选成都东站，台北选台北车站，香港选香港西九龙站，起终点明确为广州站与兰州站。澳门不选择轻轨站作为重铁代表站。没有找到所选站时不悄悄替换为同城其他站。

城市布局优先采用 OSM `place=city/town` 节点坐标并记录对象 ID；找不到时可用已经识别的代表站坐标布局，明确标为车站坐标回退；仍找不到时保留节点并在图中列出未定位城市，不填入假设坐标。城市中心坐标不参与铁路距离计算。

先验证名称与城市身份：中文规范别名优先，英文命中但中文名称冲突的候选拒绝；距独立 OSM 城市位置超过 80 km 的候选拒绝；仅英文且缺少城市位置时拒绝。名称和城市距离门槛不能代替人工核验，缺少独立城市位置的中文候选另标待审。通过后按站点本身属于有效轨道节点 → OSM `stop_area` 成员的实际停靠节点 → 150 m 内最近实际轨道 OSM 节点匹配。空间匹配使用 ECEF 搜索及 WGS84 复核，仍标为 `spatial_match_needs_review`；不添加站房到轨道的铁路边。拒绝依据及原始名称标签见 `station_candidate_rejections.csv`。

**运行后请重点人工查看广州、兰州的车站局部图，以及所有需要复核的空间匹配。** 代表站通过一个明确的实际轨道节点定义，不把同城多站或同站不同股道零代价合并；其他股道未必通过该代表节点。

## 流式提取、拓扑与距离

使用 pyosmium 两遍扫描：先存相关线路与站场/列车关系并收集所需节点 ID，再流式读取所需坐标、车站和城市布局节点。全国无关对象不加载到内存；铁路子集存入 SQLite。相关 OSM 对象按 **对象类型 + ID** 去重，取最高版本；重复数和版本/内容冲突写入质量记录。同版本冲突保留最后输入文件的数据并明确记录，不凭空间接近合并对象。

筛选当前 `railway=rail`，排除地铁、轻轨、有轨电车、废弃、在建以及 `usage=industrial/military/test/freight`、`passenger=no`、`railway:traffic_mode=freight`、`access=no/private/military`。主线/支线与未知用途可保留，未知明确标记，**不声称已确认客运可用**。

`service=yard/siding/spur/crossover` 不进入主干图；仅当选定代表站位于这些轨道上时，保留其通向主线的最短辅助轨道支路，其余站场捷径排除。其他未支持的 `service` 值也排除。该策略可能使某些真实连接不可达，应查看质量记录，不为全国连通调整筛选。

轨道只在共享 OSM 节点上连通。相交但不共享节点、不同高度的跨越以及临近双线不会自动连通。度为 2 的形状点可从图的搜索节点中简化，但保留在边的完整几何中；遇到其他线路共享节点、代表站锚点和可识别停靠节点时分割。缺失任意形状点的 way 整体排除并记录，不跨越缺点用直线补齐。

每条边的长度使用 `pyproj.Geod(ellps="WGS84")` 对折线全部相邻坐标对求椭球面距离后累计，单位 km。双线/平行线保留各自 OSM 节点与边；算法选取可用路径，**不把两条线长度相加**。搜索稀疏矩阵同端点有平行边时取最短边及其真实轨道 ID，全部实际边仍保留用于溯源。主分析为无向基础设施图，忽略行车方向、时刻表、运营与其他限制，不加入铁路渡轮或非轨道连接。

## 城市边和广州到兰州

城市边定义：两个所选代表站之间存在**不经过第三个所选代表站轨道节点**的铁路通路；允许非代表站与非省会城市；在这些通路内取最短几何里程。搜索遇到其他代表站立即停止，不继续穿越。每条城市边保存实际轨道路径、OSM way/node ID、线路名和来源。

城市图按代表站锚点屏障规则生成，可能因轨道绕过单个锚点而产生稠密甚至完全的主体分量；这不表示已确认有直达列车。用 scipy 图算法仅从广州代表节点出发计算到兰州；压缩图也仅检查这一方向的距离，两者必须一致。无全体城市距离矩阵。

线路分段按实际可识别停靠节点、线路名变化划分；未标注线路名时按 OSM way ID 变化划分。CSV 仅在识别到真实停靠站名时填写站名，其余用轨道节点 ID 追溯，形状点不称为车站。各段距离之和重新与总长度核对。

若不可达，只生成明确状态、车站匹配信息、连通分量和可疑断点记录；不会生成空路线冒充有效路径，也不会估算距离补线。底层与城市网络的有效成果仍保留。

## 缓存、日志与更新

`data/cache/rail_subset.sqlite` 缓存提取子集，`graph.pkl` 缓存轨道图；输入 SHA-256、提取/建图策略版本和代表站配置相同时复用。只加载本程序产生的本地缓存，不接收陌生来源的 pickle。更换 PBF 时先备份旧结果和 `data/raw/sources.json`，然后移除旧来源清单再运行；新 SHA-256 会让旧缓存失效。不要删除原始数据以解决程序错误。

运行日志：`logs/run_*.log`；异常堆栈：`logs/errors_*.log`；安装与测试也有单独日志。失败时 `run_status.json` 为 `failed`，旧成果不能当作本次新结果。正常阶段完成才为 `completed_real_osm`。全数据大文件扫描、SHA-256 和绘图可能需要较长时间；建议 16 GB 以上内存、32 GB 更稳妥，并留出 20 GB 以上磁盘空间，实际需求随提取版本和轨道数量变化。
